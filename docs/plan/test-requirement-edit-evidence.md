# Normal-edit requirement-change evidence

## Reproduction and cause

The regression uses the real Pi SDK session, normal bash/edit tool definitions and production extension registration in a temporary workspace. Only external classifier/completion I/O is controlled. The fixture actually executes the redirected CLI acceptance test: the hello-world process succeeds, so `a redirected shell must refuse to start` fails. No Ferrum file is edited.

The same fixture, copied into a clean `git archive af9118e` workspace, fails (one test, exit 1): normal edit refuses the obsolete-test removal and leaves its bytes unchanged. With this fix the fixture succeeds. The final full suite passes 2,109 tests; the real live Jev fixtures pass 20/20. Independent review requested an additional deterministic whole-file deletion case with unresolved assessment and a once departure: that case also fails against af9118e (the old gate actually empties the fixture) and passes with this fix, including unchanged bytes and the unspent departure. Initial SDK fixture attempts accidentally inherited `NODE_TEST_CONTEXT` and skipped nested tests; the corrected fixture explicitly unsets it and asserts the real RED result. Both classifier and completion provider boundaries are isolated to avoid ambient classifiers influencing the offline SDK scenarios.

The intercepted assessment previously omitted applicable departure rationale. Test-run recording also did not recognize `nix develop --command cargo test ...`, and its three-line summary could discard the actual assertion failure. Consequently direct `judge_test_change` calls supplied with full failure evidence and normal edit assessments were not equivalent inputs. The departure check occurred after assessment, so it could not repair missing assessment evidence. A recorded departure is now assessment evidence, not unconditional authorization: every proposed change is still assessed, and unresolved assessment cannot spend a departure or permit deterministic deletion.

A resolved complete primary assessment already returns directly from the cascade. The direct diagnostic tool does not authorize later edits; no cross-tool judgment reuse was added. Existing primary caching includes state and questions, so changed before/after text, failure evidence or departure evidence changes the cache key. A partially unresolved batch still escalates as one batch. No confidence threshold was changed and no uncertainty is converted into a permission request.

## Scope and diagnostics

Only open departures applicable to the active slice (or once/session scope) enter the test-change assessment. An identified requirement change requires a departure even at low weakening probability, ensuring a once decision is consumed. Tests exercise obsolete characterization removal, still-required assertion loss and whole-file deletion, stale slice, consumed once decision followed by a different edit, and absent RED evidence. Every rejected SDK edit checks the target bytes remain unchanged.

Reasoning failures distinguish `reasoning.json`, `reasoning.schema`, `reasoning.answers` (including low confidence and inconsistent distributions), `reasoning.evidence`, `reasoning.provider`, `reasoning.timeout` and `reasoning.completion`. Edit failures identify `tests.weaken assessment` and the affected path. Provider exceptions are not echoed. Evidence is bounded and secret-redacted before persistence and assessment; explicit missing-evidence reasons are redacted, control-sanitized and bounded before display. Existing model-routing failures already state the missing configuration/model or excessive evidence size. A provider-reason regression generates fake credentials at runtime and checks credential redaction, removal of terminal/control characters and the 500-character displayed-reason bound.

This checkout started at af9118e/version 9.0.0; the proposed release is 9.1.0 (the semantic-version gate requires a minor bump). Package files on disk alone do not prove historical in-memory code. Updating packages does not by itself establish which implementation an already-running Ferrum session used. The original generic error erased the failed stage; the precise historical model response cannot be reconstructed from that message alone. The verified claim is the missing-evidence defect reproduced through interception, not a claim that Ferrum's original failure was a confidence-threshold failure.

Offline fixture results prove evidence transport, scope policy and normal-tool effects, not perfect live-model judgment for all contracts. The existing live test-change fixtures also pass; the Ferrum-shaped requirement/departure scenario is tested deterministically at the provider boundary, not asserted to be a live-model success. Long failure output is bounded and may still require a narrower actual test run. Applicable departure rationale remains evidence to evaluate, not proof of arbitrary assertions made by an agent.
