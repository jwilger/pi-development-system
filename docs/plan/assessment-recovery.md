## recovery — Recover uncertainty without transferring it to the owner

**Goal:** A caller can inspect a recoverable assessment failure, supply an existing contract for the exact proposed test edit, and retry through the normal gate without obtaining new approval.

**Files:** src/jev/client.ts, src/jev/cascade.ts, src/jev/reasoning.ts, src/jev/questions/test-change.ts, src/gates/test-guard.ts, new contract evidence adapter, extensions/development-system.ts, principles/NON-NEGOTIABLES.md, test/gates/assessment-recovery.test.ts, assessment tests and guidance evals, ARCHITECTURE.md and ADR 0018.

**Interfaces:** Keep assessment-unresolved as the fail-closed outer error kind; carry insufficient-evidence, invalid-output and infrastructure categories as data. Supply contract evidence bound to workspace, slice, normalized path and exact before/after contents. Evidence is not authorization or a verdict.

**First failing test:** Normal SDK edit in a temporary workspace retains the file and returns insufficient-evidence with a supported contract recovery action for unresolved motive.

**Steps:**

1. Record the actual evidence and uncertainty propagation and compare installed code separately.
2. Reproduce the missing recovery contract through production SDK hooks.
3. Add structured causes and exact-edit-bound evidence submission; reassess normally.
4. Exercise adverse outputs and legitimate authorization decisions without changing thresholds.
5. Verify model-facing recovery behavior with an executable agent eval and obtain independent review.

**Run:** node --experimental-transform-types --no-warnings --test test/gates/assessment-recovery.test.ts

**Expected:** All recovery cases pass, with no denied mutation executed and no uncertainty converted into authorization. Initial run: 0 pass, 1 fail; existing diagnostic lacks insufficient-evidence and a supported recovery action.

**Out of scope:** Ferrum edits, resuming its goal, modifying the external goal plugin, installation, publication or remote delivery without authorization.

## Threat assessment

Assets: test-oracle integrity, approval authority and evidence confidentiality. Model-supplied evidence and proposed file contents are untrusted, never approval. The evidence tool must not execute a command or write a target file. Bind evidence to the exact workspace/slice/path/before/after; clip and redact before model dispatch; stale or unrelated evidence must not apply. Malformed responses and provider failure remain closed; only genuine authorization follows existing departure/approval controls. No new dependencies or external calls. Session-local evidence disappears on reload, requiring resubmission; this is safer than treating stale evidence as authorization.
