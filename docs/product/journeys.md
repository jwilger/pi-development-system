# Repository-owned workflow adoption journeys

Revision 0.2 — proposed; goal confirmation authorized planning only.

| ID | User and starting need | Actions | Outcome |
| --- | --- | --- | --- |
| J01 | Owner needs to understand inherited workflow | Survey guidance/tooling/automation/board read-only; separate intent, observation and unknowns; resolve conflicts with owner | Evidence-backed local policy, not accidental legacy state treated as authority |
| J02 | Owner needs new or revised local workflow | Choose consequential policies, review local document/config diffs and explicit migration/pilot plan | Discoverable version-controlled project-owned authority |
| J03 | Developer needs one item under local policy | Read actual lifecycle/fields and local selection guidance; explicitly enroll, assign, comment or set a field only when authorized | Local ownership/blocking conventions without a universal state graph or claim rule |
| J04 | Owner needs local concerns applied in review | Configure workflow/review inputs, start fresh review, inspect typed results under unchanged input identity | Fresh reviewers actually receive local concerns while upstream review rules remain intact |
| J05 | Elixir developer needs idiomatic help | Detect/override profile; use declared local commands, behavior tests and idiomatic error values | No imposed architecture, library or Rust/TS domain pattern |
| J06 | Developer needs truthful resumable evidence | Finish local slices, inspect explicit PR references, resume checks and apply configured supported conditions | Push/open PR is not reported as delivered work; manual/unknown evidence stays visible |
| J07 | Owner needs distinct workflows to coexist | Exercise product PR workflow and human-led research using identical upstream code | No hardcoded queue, self-claim, merge policy or auto-close |
| J08 | Developer needs safe recovery | Inspect missing permissions/config/membership or uncertain/partial effects; re-read before retrying authorized missing operations | No silent provisioning, rollback of human changes or false success |

Issue lifecycle, Project fields, local slice phase and delivery evidence remain separate.
Missing/contradictory authority needs owner resolution, not a fallback invented by an agent.
The [slice plan](../plan/existing-application-adoption.md) provides contracts and first
failing scenarios. ADRs 0011–0013 are proposals; no implementation approval is recorded.
